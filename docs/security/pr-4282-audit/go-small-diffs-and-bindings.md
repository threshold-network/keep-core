9. `pkg/tbtc/node_executors.go` - `newCoordinationExecutor` call now passes `n.ethereumNetwork` (a new second parameter) in addition to `n.chain`. This is what the tBTC node executor's reservation-activation decision depends on: `pkg/tbtc/coordination.go:713` and `:745` use `ce.ethereumNetwork` to compute `ReservationsActivationBlock(ce.ethereumNetwork)` and gate reservation actions (`ActionReservationAnchor`, `ActionReservationReanchor`). Before this change the field existed on the struct but the constructor's new argument was the only code path that could set it correctly; passing `n.ethereumNetwork` (already the value `newNode` stores, `pkg/tbtc/node.go:125-156`) is the correct source. A wrong value here (e.g. `ethereum.Unknown`/zero) would make `ReservationsActivationBlock` return `math.MaxUint64` (`pkg/tbtc/coordination.go:110-120`) and silently disable all reservation actions - which is the documented "fail closed" design (confirmed by `coordination_test.go:1125-1127` "unknown network never activates (fails closed)"). This is the correct value being passed, and a misconfiguration would fail closed, not open. No finding.

10. `pkg/protocol/state/sync_machine.go` - Error-message improvement: added `: [%w]` to `failed to wait for the execution start block`. No behavior change. No finding.

11. `pkg/tecdsa/dkg/message.go` - `ephemeralPublicKeys` map value type changed from `*ephemeral.PublicKey` to `[]byte`, with the `github.com/keep-network/keep-core/pkg/crypto/ephemeral` import dropped. This is a deliberate deferred-parse optimization (commit `dfb578f11 perf(tecdsa): defer ephemeral key parsing from O(N²) to O(N)`): each DKG round message carries N-1 full curve public keys, and parsing them all eagerly at unmarshal time was O(N) work per message, O(N²) total across all messages. Now the raw bytes are stored at unmarshal time and each key is parsed lazily, only for the one key the local member actually needs for ECDH (`pkg/tecdsa/dkg/protocol.go:84-85`). Validation: the only use is at `pkg/tecdsa/dkg/protocol.go:84` via `ephemeral.UnmarshalPublicKey`, which calls `btcec.ParsePubKey` and returns `ErrInvalidPublicKey` on failure; the caller treats that as "mark this sender inactive and continue" rather than a fatal round error (comment at lines 87-94 documents this is the pre-existing behavior preserved intentionally, matching pre-PR semantics where a malformed key would have failed whole-message unmarshaling and dropped the message). A malformed key still can't produce a wrong symmetric key: an unparseable key is skipped, not parsed into a wrong value. No finding.

12. `pkg/tecdsa/signing/message.go` - Identical change to item 11, applied to the signing protocol's `ephemeralPublicKeyMessage`. Same analysis, same conclusion. No finding.

13. `pkg/maintainer/maintainer.go` - `Initialize` gains a `metricsRecorder spv.MetricsRecorder` parameter, forwarded to `spv.Initialize`. Confirmed the sole production caller, `cmd/maintainer.go:82-89`, passes a real value (`initializeMaintainerMetrics`, which returns either a `clientinfo.PerformanceMetrics` or a literal `nil` typed as the interface). The `nil` case is safe because every use site in `pkg/maintainer/spv/` guards with `if metricsRecorder != nil` before calling a method (verified in `deposit_sweep.go`, `redemptions.go`, and the reservation-loop files). This is not a "typed nil interface" bug: `initializeMaintainerMetrics`'s return type is the concrete interface `spv.MetricsRecorder`, and returning the untyped `nil` literal (line 122) correctly produces a nil interface value, so `metricsRecorder != nil` is a correct check. No finding.
