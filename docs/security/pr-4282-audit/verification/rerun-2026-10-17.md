## Corrections

Two corrections to earlier versions of this note:

1. The first version (and later ones) said 61 killed and 58 survived before the
   survivor tests, and "15 killed by new tests". Two of the 58 were killed by existing tests:
   `TestReservationAnchorAction_PendingRecheck` and `TestReservationReanchorAction_PendingRecheck`
   fail an assertion under the "not a pending acceptance" and "not a pending reanchor" mutants,
   and the next subtest then hangs until the 90 s test timeout. The harness recorded a stage-1
   timeout and, because the two slow tests passed in stage 2, the final column said `survived`.
   That version also said "0 timeouts"; it was 2.
2. Earlier versions placed each survivor on the first removed line of its diff. For
   the two mutants that remove the multi-line soft fee warning call in each `execute`, that line
   is a comment, which is in no coverage block, although the call is executed. So the survivors
   on executed statements were 16 before the tests and 3 after them, not 14 and 1, and the
   score without unexecuted and no-block survivors was 79.7% and 96.2%, not 81.8% and 98.7%.

## Why

The earlier pilot got a verdict for 2 of 147 mutants of `pkg/tbtc/reservation.go`, with 57
timeouts, so the file had no usable mutation score (`mutation-pilot.md`, and the gap list in
`rerun-2026-10-14.md`). The cause of the timeouts: two tests,
`TestReservationReanchorAction_Success` and `TestReservationAnchorAction_Success`, take 60 s
each, and the pilot ran the whole package suite for every mutant. `rerun-2026-10-14.md` also
listed `pkg/tbtc/reservation_target_age.go` and the keeper observer as not covered.

## How

- Tool: `go-mutesting`, all default mutators, one worker, one file per run, custom exec script.
  Go 1.25.7.
- `reservation.go`: stage 1 per mutant is `go test ./pkg/tbtc -run Reservation` with the two
  60 s tests skipped (90 s test timeout); stage 2, only for a stage-1 survivor or timeout, runs
  the two 60 s tests. Four runs: keep-core the public candidate (run 2,
  before any survivor test), a mutation-tooling branch (run 4),
  run 5 and run 6 (2026-10-18). `reservation.go` is byte-identical
  in runs 2, 4 and 5; run 6 has the broadcast timeout field of the later action-field refactor. Runs 5 and 6 check
  for a `--- FAIL` line before a timeout. Run 6 survivors are matched to run 5 by diff body
  (`go-mutation-reservation/run6/match-run5.tsv`), and all 35 run-6 build rows were re-compiled
  and fail.
- `reservation_target_age.go` at the public candidate: `TestIsReanchorTargetAged` and
  `TestReservationReanchorAction_RejectsYoungTarget` per mutant.
- Keeper observer, `pkg/maintainer/spv/reservation_keeper_observer.go` and
  `reservation_keeper_risk.go`: `go test ./pkg/maintainer/spv -run '^TestReservationKeeperObserver_'`
  per mutant, on the drill-fix branch @ `9c4e1b221` and then on
  the mutation-tooling branch @ `43a1bd046` and `fc05d9059`.
- Harness checks: an unchanged copy survives; a known breaking mutant is killed; each source
  file was identical to its commit after every run; every run has one verdict row per mutant.
- Survivors were triaged by reading the code (`go-mutation-reservation/triage/`,
  `go-mutation-keeper/equivalence-review.md`). Every new test was run against its mutant
  (fails) and the original (passes).
- An earlier attempt of run 4 ran out of disk space and stopped at 120 mutants. It is not a
  result. In run 5 one mutant was reported as a build failure; re-compiled alone it builds and
  a new test kills it, so it is counted as killed (`run5/build-recheck.tsv`).

## Survivor tests

All on private branches; nothing is on a public remote.

- a keep-core mutation-tooling branch, on top of the public candidate:
  - `pkg/tbtc/reservation_mutation_survivors_test.go` (one test renamed in run 4) kills 13 of the 16 executed survivors: the six assemble boundaries, the
    expiry margin in both `execute` paths, the funding fetch failure, the funding output index
    filter, the transaction monitor in both constructors, and the result channel size 1 to 0.
  - `pkg/tbtc/reservation_mutation_survivors_paths_test.go` (added in run 5) kills 11 survivors on
    unexecuted statements: a Bridge validator error that the mutant drops (the test also checks
    that signing is never reached), dropped chain read errors and dropped assembly errors in
    both `execute` paths, and three assembly input checks. Under four of these mutants the code
    dereferences nil and panics. On 2026-10-18 this file was split into
    `reservation_mutation_survivors_{anchor,reanchor,assemble}_paths_test.go` (later split by
    action, code moved unchanged, same test names).
  - the later action-field refactor makes the broadcast timeout and check delay fields of both reservation actions,
    set from the same constants (human decision 2026-10-18). The two broadcast-error tests now
    run by default with a 300 ms timeout (0.3 s each). Hand check: replacing each action's
    broadcast error return with `return nil` fails the matching test, and the original passes.
    Run 6 confirms it: both mutants are killed.
- a keep-core mutation-tooling branch, on top of `9c4e1b221`:
  46 tests in `43a1bd046` and 4 more in `fc05d9059`. They kill 74 of the 85 keeper survivors,
  including three tests of the `Run` loop, which had none. `1e044baff` splits the single test
  file into eight `reservation_keeper_mutation_survivors_*_test.go` files of 500 lines or fewer
  (code moved unchanged, same test names).

A first pass at the keeper survivors labelled 12 mutants equivalent with only "the filter
still passes" as evidence. A code review found that 4 of them change behavior (a fetch on the
no-scan path, a reveal routed to another vault being tracked, the refund-deadline underflow
guard, a nil-data wallet hiding a later target); the second keeper commit kills those 4.
